1. The idea, with Alice in it

Alice invoices clients with Ledger. An agent built Ledger from a one-page PRD that never said "a user must not see another user's invoices". So Alice can type /invoices/4 and read Bob's $4,000 invoice, and every test is green. Bugsy finds that, fixes it, proves the fix, and proves the proof.

2. Where the originality points come from

  1. Spec-driven, not payload-driven. The input is an ownership rule in plain English. OpenAI derives the scenarios from the rule and the routes. Each scenario is a readable requirement before it is a test.
  2. Every denial has an owner control. "Alice is denied" only counts if "Alice still opens her own invoice" passes. A patch that breaks the app fails. Scanners only look for the leak.
  3. The seatbelt checks itself. After the fix, Bugsy reverts the patch and reruns. If the scenario doesn't go red, it wasn't testing anything. No security tool in the room proves its own tests.

Plus the Kane angle the rubric names: Kane is the eyes of the patching agent. Codex fixes from Kane's failure record and screenshot, not from an HTTP response.

5. How a verdict is decided

flowchart TD S([Kane run finished]) --> Q0{Sign-in steps passed, nothing broken or interrupted?} Q0 -->|no| INC[inconclusive: environment, not security] Q0 -->|yes| Q1{Owner control S1 passed?} Q1 -->|no| INC Q1 -->|yes| Q2{Leak scenario S2 passed?} Q2 -->|yes| OK[denied as expected] Q2 -->|no, failed at the denial step| LEAK[leak confirmed]

A failed sign-in, a timeout or a broken app is never "secure". The control is what makes a denial mean something. bugsy patch commits only when S1, S2 and S3 all pass on the patched app.

9. What you decide now

  • scope Three scenarios in the MVP: S1 owner control, S2 read by URL (the leak), S3 list isolation. S4 write check is opt-in after C3.
  • fixture Commit A ships vulnerable on purpose and we say so. No hidden switch; git is the fixture.
  • patcher Codex CLI by default, Responses API fallback, prepared four-line patch as last resort, announced.
  • credits Only you run Kane against credits. Agents build against recorded output from C1.
  • hub Update the idea text in the hub to the v2 one-liner. Pair, consent, confirm the defect, tick runs, Submit tab fields.
